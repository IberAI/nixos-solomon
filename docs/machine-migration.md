# Machine Migration Checklist

What to carry to a fresh install of this configuration, and — just as
important — what must **not** be carried, because Home Manager refuses to
activate over files it wants to own.

Copy with `rsync -aH` or `cp -a` so ownership, modes and hardlinks survive.
`~/.ssh` and `~/.gnupg` must end up mode `700`, private keys `600`.

---

## 1. Required — the configuration references these by path

Without these, Git has no identity and the SimpleX wrapper refuses to start.

| Path | Start from |
| --- | --- |
| `~/.ssh/config.local` | `templates/ssh-config.local.example` |
| `~/.config/git/local.inc` | `templates/git-local.inc.example` |
| `~/.config/simplex/smp.env` | `templates/simplex-smp.env.example` |

## 2. Secrets and identity

```text
~/.ssh/          keys and known_hosts — but NOT ~/.ssh/config, see §5
~/.gnupg/        keyring and trustdb — but NOT ~/.gnupg/gpg.conf, see §5
```

Plus the KeePassXC `.kdbx` and any accompanying key file. Nothing in this
configuration pins where that database lives, so it is on you to remember.

## 2a. Git consistency

Git behaviour comes from four places. `~/.config/git/config` is generated by
Home Manager, so the parts that make *your* Git yours are all elsewhere:

```text
~/.config/git/local.inc      identity, signing key, any url rewrites  (§1)
~/.gnupg/                    the secret key commit signing uses       (§2)
~/.ssh/                      the keys your remotes authenticate with  (§2)
~/Development/               the repositories themselves
```

Copying `~/Development` is what preserves the state that only exists locally:
stashes, unpushed branches, reflogs, per-repository `.git/config` overrides,
hooks, and worktrees. None of that lives anywhere else.

If you use the Codeberg helper, `scripts/setup-codeberg-private.sh` expects
`~/.ssh/id_ed25519_codeberg` and appends a `Host codeberg.org` block to
`~/.ssh/config.local`. Copy the key and that block, or re-run the script.

After switching, confirm the identity actually resolves through the include:

```sh
git config --global --includes --get user.name
git config --global --includes --get user.email
gpg --list-secret-keys          # signing key present?
ssh -T git@codeberg.org         # remote auth works?
```

## 2b. Browser consistency

The Mullvad Browser profile lives at:

```text
~/.mullvad/mullvadbrowser/
```

That is the whole profile root — `profiles.ini` plus one
`<random>.<name>/` directory holding bookmarks, history, saved logins,
extensions, cookies and preferences. Copy the entire `~/.mullvad/` tree.

Verified by running the packaged browser under a scratch `HOME`; the path is
*not* the `~/.mullvad-browser` that the bundled `start-mullvad-browser` script
would use, because nixpkgs wraps the ELF binary directly and never runs that
script.

`home/apps/browsers.nix` sets `MOZ_LEGACY_PROFILES=1`, and that setting is what
makes any of this survive. Firefox normally binds a profile to the installation
directory it was created from, recorded as an `[Install<hash>]` section in
`profiles.ini` and in `installs.ini`. On NixOS the installation directory is a
Nix store path that changes on **every browser update**, so without this
variable the browser would decide it was a new installation and hand you a fresh
empty profile — on upgrades as well as on migration. Keep it set.

Close the browser before copying, so `places.sqlite` and friends are not
mid-write.

Background: [profile per installation](https://support.mozilla.org/en-US/kb/understanding-depth-profile-installation)
and [the bug that added the opt-out](https://bugzilla.mozilla.org/show_bug.cgi?id=1528082).

## 3. Other application state

```text
~/.simplex/main                 SimpleX database (matches solomon.simplex.profile)
~/.config/obs-studio/           scenes and profiles — contains your stream key
~/.config/gpu-screen-recorder/  stream keys and the portal restore token
~/.local/share/nvim/            Neovim plugins
~/.local/state/nvim/            Neovim undo history and shada
~/.local/share/fish/fish_history
~/.local/share/direnv/allow     so direnv does not re-prompt in every repo
~/.emacs.d/                     everything EXCEPT init.el, see §5
```

Then the remaining data: `~/Documents`, `~/Pictures`, `~/Tools` — `~/Development`
is covered in §2a. The Home Manager activation script recreates those
directories, but never their contents.

## 4. System state — needs `sudo`

```text
/etc/NetworkManager/system-connections/   every saved Wi-Fi password
/var/lib/bluetooth/                       device pairings
/var/lib/i2pd/                            router identity and netDb (optional)
/var/lib/tor/                             optional, regenerates
/var/lib/docker/                          images and volumes; large, or re-pull
```

The NetworkManager directory is the one most often forgotten, and losing it
means no network on the new machine.

## 5. Do not copy — Home Manager will refuse to activate

Home Manager symlinks these out of the Nix store. A real file sitting at any of
them aborts activation with `Existing file '…' is in the way of …`, and the
whole switch fails.

```text
~/.ssh/config                     ~/.config/mako/config
~/.config/git/config              ~/.config/i3status-rust/config-top.toml
~/.config/fish/config.fish        ~/.config/sioyek/prefs_user.config
~/.config/fish/functions/         ~/.config/udiskie/config.yml
~/.config/kitty/kitty.conf        ~/.config/user-dirs.dirs
~/.config/kitty/diff.conf         ~/.config/user-dirs.conf
~/.config/sway/config             ~/.gnupg/gpg.conf
~/.emacs.d/init.el                ~/.manpath
~/.config/fontconfig/conf.d/*hm*
~/.config/environment.d/10-home-manager.conf
~/.config/direnv/lib/hm-nix-direnv.sh
~/.config/systemd/user/{sway-session.target,tray.target,udiskie.service,…}
```

Also skip `~/.config/nvim`. NvChad runs with `hm-activation = true`, so Home
Manager writes that directory itself. It has `backup = true`, so a stray copy is
renamed rather than fatal, but it is noise either way.

## Order of operations

1. Install NixOS 26.05 and generate a **fresh**
   `hosts/nixos/hardware-configuration.nix` on the target machine:

   ```sh
   nixos-generate-config --show-hardware-config
   ```

   Never reuse one generated on different hardware — the initrd module list is
   machine-specific, and a wrong one means the root filesystem is not found.

2. Clone this repository and check out the `native` branch.

3. Copy sections §1 through §4.

4. Verify before switching:

   ```sh
   nix flake check
   sudo nixos-rebuild test --flake .#nixos
   ```

5. Switch:

   ```sh
   sudo nixos-rebuild switch --flake .#nixos
   ```

If activation complains that a file is in the way, that file belongs to §5.
Delete it and re-run.

## After first boot

- Confirm the keyboard is Turkish at the `tuigreet` prompt. If not,
  `console.keyMap` did not apply — check `modules/locale.nix`.
- Re-pair Bluetooth devices if `/var/lib/bluetooth` was not copied.
- Create stream keys as needed:

  ```sh
  install -Dm600 /dev/stdin ~/.config/gpu-screen-recorder/twitch.key
  ```

- `gpg --list-secret-keys` should show your keys; if not, re-import and run
  `gpg --edit-key <id> trust`.
